# CentralPDF 2.0.0-alpha.2

Segundo pré-lançamento público da nova arquitetura CentralPDF 2.0, desenvolvida com Vite, React e TypeScript e voltada ao processamento local de documentos.

Esta versão corrige a publicação visual da interface 2.0 no GitHub Pages, quebrada na 2.0.0-alpha.1, e restaura o design de produção da interface.

## Correções nesta versão

- **Estilos de produção restaurados no GitHub Pages**: a folha `app/src/styles/components.css` (cards de ferramentas, botões, campo de busca, badges, grid) foi adicionada em `eda8f4f` mas nunca importada por `app/src/main.tsx`; o site publicava apenas os tokens de tema. O import ausente foi corrigido (commit `4b26c66`) e o CSS final passou de ~3,5 kB para ~11 kB.
- **Revert do merge de deploy quebrado**: o merge `50fd117` (PR #24), que publicava a interface legada 1.2.1 no lugar da CentralPDF 2.0, foi revertido com `git revert -m 1` (commit `b724c90`) sem reescrever histórico.
- **Pacote web completo**: o pacote de distribuição (`CentralPDF_Web_Local_v2.0.0-alpha.2.zip`) e o site do GitHub Pages passam a usar exclusivamente o `app/dist` (aplicativo 2.0), incluindo fontes padrão do PDF.js, PDF.js, QPDF WASM e os utilitários locais.
- **Teste de produção da interface**: novo `tests/production-ui-2.0.test.py` valida o build publicado com Playwright — estilos computados (grid, cards, busca, badges, cabeçalho), ausência de erros de console/recursos 404/500, ausência de overflow de layout em desktop (1366×768) e mobile (390×844) e screenshots em `tests/screenshots/2.0.0-alpha.2/`.

## Qualidade

- Validações locais aprovadas: `npm ci`, typecheck (`tsc -b --noEmit`), Vitest, build de produção, teste Playwright de produção (GitHub Pages e pacote local), suite Python legada, suite JavaScript legada, `go test ./...`, `go vet ./...`, builds Windows reprodutíveis (`cmp` byte a byte), ZIP e SHA-256.
- Sincronização de versão verificada entre `app/package.json`, `app/package-lock.json`, `BUILD_VERSION` em `app/src/App.tsx`, `appVersion` em `server/main.go`, `README.md` e `docs/releases/2.0.0-alpha.2.md`.

## Publicação

- O workflow `pages.yml` publica somente `app/dist` no GitHub Pages, após build, testes e teste de produção da interface; o deploy ocorre apenas na `main`.
- O workflow `release.yml` é acionado por tag (`v2.0.0-alpha.2`) ou `workflow_dispatch`, publica como pré-lançamento (SemVer com sufixo), gera dois builds do servidor Windows e exige `cmp` idêntico antes de empacotar.
- Nenhum asset de release existente é substituído; se a tag já existir apontando para outro commit, o workflow falha.

## Observações de pré-lançamento

Esta é uma versão `alpha`. Algumas ferramentas ainda estão experimentais ou planejadas e podem mudar antes da versão estável 2.0.0. O aviso de chunks grandes no build é conhecido e será tratado posteriormente com divisão de código e carregamento sob demanda.

### Recomendação sobre a 2.0.0-alpha.1

A publicação da `2.0.0-alpha.1` foi feita pelo merge da PR `#24` (commit `50fd117`), que quebrou a aparência da interface publicada. O defeito visual veio da ausência de import do `components.css` em `main.tsx` (corrigido nesta versão). Após a publicação desta versão, recomenda-se editar a descrição da release `v2.0.0-alpha.1` no GitHub (apenas a descrição, sem excluir a release nem seus assets):

- adicionar no início um aviso de que a versão publicou uma interface com aparência quebrada devido ao import de CSS ausente, atribuindo a publicação ao merge da PR `#24`;
- recomendar a adoção da `2.0.0-alpha.2` (ou posterior);
- manter a release e os assets intactos para preservar histórico e rastreabilidade.
